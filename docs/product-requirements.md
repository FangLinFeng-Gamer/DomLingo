## 1. 产品概述

DomLingo 是一个纯网页翻译扩展。用户安装后无需注册、登录或购买会员，只需配置自己的 OpenAI-compatible 模型服务，即可将当前网页的英文正文原位翻译为简体中文。

DomLingo 不接管 Chrome 原生的“翻译成中文”菜单，而是提供独立的“翻译当前页面”操作。它不重建网页、不让模型生成 HTML，主要通过修改原页面文本节点来呈现译文。

产品承诺是“最大限度保持页面结构、样式和交互”，而不是翻译前后的像素级布局完全一致。中英文长度不同仍可能引起自然换行和元素尺寸变化。

DomLingo 的内容使用边界是：用户已经合法打开公开网页，由用户主动点击翻译，译文只显示在用户自己的浏览器中。DomLingo 是阅读翻译工具，不是访问控制、付费墙或版权绕过工具。

## 2. 背景与问题

现有网页翻译方案通常存在以下问题：

- 默认翻译引擎质量不能满足用户需求；
- 高质量模型与账号、会员或额度体系绑定；
- 自带 API Key 的能力可能仍要求登录或订阅；
- 双语插入、侧边栏展示会改变阅读方式；
- 功能覆盖 PDF、字幕、OCR 等过多场景，设置复杂；
- 动态页面容易漏翻、重复翻译或破坏交互；
- API Key、网页正文流向和隐私边界不够清晰。

DomLingo 解决的问题是：让用户以最短路径使用自己的大模型，在原页面中获得稳定、自然、可恢复的中文正文。

## 3. 产品目标

### 3.1 MVP 目标

- 用户在不创建 DomLingo 账号的情况下完成模型配置；
- 一键翻译当前网页的英文正文；
- 优先翻译当前视口内的正文内容；
- 翻译 React/Vue 等页面后来新增并进入可视区域的正文；
- 不修改页面元素层级、class、内联样式、链接地址和事件；
- 支持随时停止翻译和逐节点失败保护；
- 支持一键精确恢复原文；
- 支持 OpenAI-compatible 服务、预设服务和本地 Ollama；
- 支持本地翻译缓存、自定义 Prompt、配置导出与安全同步；
- 明确告知用户网页文字会发送到其选择的模型服务。

### 3.2 非目标

MVP 不包含：

- 替换或接管 Chrome 原生翻译入口；
- DomLingo 用户账号、云端后端或订阅系统；
- 中英双语对照插入；
- 翻译导航栏、全局侧边栏、页脚、广告等非正文区域；
- 中文以外的目标语言；
- 英文以外的源语言；
- PDF、EPUB、视频字幕、会议字幕、OCR、漫画或图片文字翻译；
- Canvas 文字、跨域 iframe、closed Shadow DOM 的完整翻译；
- 网站级自动翻译规则；
- 商业术语库和团队协作；
- Firefox、Edge、Safari 的正式发布；
- 翻译后像素级布局完全一致；
- 绕过登录、订阅、付费墙、DRM 或其他访问控制；
- 批量爬取、下载或建立网站内容镜像；
- 导出、托管或公开分享完整网页译文。

## 4. 目标用户

### 4.1 主要用户

- 经常阅读英文技术文档、博客、新闻和知识页面的中文用户；
- 已有 DeepSeek、OpenRouter、OpenAI、硅基流动等模型 API 的用户；
- 使用本地 Ollama 或公司内部 OpenAI-compatible 服务的用户；
- 不希望注册翻译插件账号或购买插件会员的用户；
- 重视网页结构、链接和交互不被破坏的用户。

### 4.2 使用前提

用户至少具备以下一种条件：

- 拥有受支持模型服务的 API Key；
- 可以访问无需 Key 的本地 Ollama 兼容端点；
- 可以访问公司内部的 OpenAI-compatible 服务。

BYOK 不代表模型调用免费。DomLingo 不收取模型费用，费用和数据处理规则由用户选择的模型提供商决定。

## 5. 产品原则

1. **纯粹**：只解决网页正文翻译，不堆叠外围功能。
2. **本地优先**：配置、密钥和缓存默认保存在用户浏览器中。
3. **最小权限**：安装时只申请基础权限，模型域名在用户操作时按需授权。
4. **结构保护**：不重建 DOM，不接收或注入模型返回的 HTML。
5. **明确可逆**：每个被替换的节点都必须可以恢复为精确原文。
6. **失败隔离**：单个节点失败不影响其他节点，也不破坏页面。
7. **隐私透明**：清楚展示正文发送到哪个服务，不暗中中转或埋点。
8. **合法访问**：只处理用户已合法打开的公开网页，不提供访问控制绕过能力。
9. **用户触发**：不在后台批量扫描或自动翻译未由用户主动选择的网页。
10. **浏览器内呈现**：译文用于当前浏览器标签页阅读，不提供完整译文发布能力。

## 6. 核心用户流程

### 6.1 首次配置

1. 用户安装并打开 DomLingo。
2. 扩展发现尚未配置模型，展示“前往设置”。
3. 用户选择预设服务或“自定义 OpenAI-compatible”。
4. 用户填写 API 地址、API Key 和模型名称。
5. 用户点击“测试连接”。
6. 扩展解析 API 地址，并请求访问该模型域名的运行时权限。
7. 测试通过后保存配置。
8. 普通配置进入浏览器同步存储；API Key 默认只保存在本机。

### 6.2 翻译当前页面

1. 用户在英文网页点击 DomLingo 图标。
2. 弹窗显示当前页面可用状态和模型名称。
3. 用户点击“翻译当前页面”。
4. 扩展定位正文区域并统计可翻译内容。
5. 当前视口中的正文优先进入翻译队列。
6. 译文按批次返回并逐节点写入原网页。
7. 弹窗和页面浮层显示进度、成功数、失败数和停止按钮。
8. 翻译完成后，扩展继续观察正文区域中新出现的内容。

### 6.3 停止与恢复

- “停止翻译”终止尚未完成的请求，并阻止新的译文写入；已经成功替换的节点保留译文。
- “恢复原文”将当前会话中所有已替换节点恢复为开始翻译时的精确文本和属性值。
- 已从 DOM 中移除的节点忽略；其他节点继续恢复，不进行页面级失败回滚。
- 关闭扩展 Popup 不停止翻译；翻译会话由当前网页和后台共同维护。
- 关闭标签页、刷新或发生跨文档导航时，自动停止当前会话，取消尚未完成的客户端请求，并禁止迟到响应写回。
- SPA 路由切换时先取消旧正文 generation；若翻译模式仍开启，再为新正文建立 generation，旧页面响应不得写入新页面。
- 请求取消是客户端尽力而为；已经到达模型服务并开始处理的请求仍可能产生服务商费用。

### 6.4 跨设备配置

- 端点、模型、Prompt 和行为设置可以通过 Chrome Sync 同步。
- API Key 默认不进入同步存储。
- 用户主动开启“加密同步 API Key”时，需要设置独立口令；同步内容仅包含密文。
- 新设备收到密文后，必须输入口令解密，再将明文 Key 保存到该设备本地。
- 口令不保存、不上传，DomLingo 无法找回。

## 8. 页面与交互状态

### 8.1 弹窗结构

```text
DomLingo · 原页译
模型：DeepSeek / deepseek-chat

[ 翻译当前页面 ]
[ 恢复原文     ]

状态：已翻译 38 / 52，失败 1
[ 停止翻译 ]

[ 设置 ]
```

### 8.2 设置页结构

```text
翻译服务
  服务预设
  API 地址
  API Key
  模型名称
  [测试连接]

翻译设置
  目标语言：简体中文（固定）
  自定义 Prompt
  动态正文翻译
  并发数
  单批字符数

缓存与数据
  启用缓存
  清空缓存
  导入 / 导出
  Chrome 同步
  加密同步 API Key

隐私与权限
  已授权 API 域名
  撤销域名权限
  隐私政策
```

### 8.3 错误文案原则

错误消息必须说明用户下一步可以做什么，例如：

- “当前页面不允许扩展运行，请换一个普通网页。”
- “未识别到正文区域，本页未进行任何修改。”
- “API Key 无效，请检查模型服务配置。”
- “模型返回格式不完整，17 个节点保留原文，其他节点已翻译。”
- “未获得 api.example.com 的访问权限，无法测试连接。”

不得只显示状态码或原始异常堆栈。

## 9. 非功能需求

### 9.1 安全

- 扩展包内不包含 DomLingo 公共模型 Key；
- 不执行远程代码；
- 网页正文一律视为不可信数据；
- 模型结果不得作为 HTML、脚本、URL 或 CSS 注入；
- API 请求只能由扩展后台发起；
- Content Script 不得读取 API Key；
- 域名权限按需申请并允许撤销。

### 9.2 性能

- 扫描 5,000 个候选文本节点时，单次同步主线程占用不得超过 50 ms；需要分片处理；
- 翻译队列不得无限增长；
- 对动态变化至少进行 300 ms 去抖；
- 模型响应到达后，可见节点应在 100 ms 内完成写入；
- 缓存查询不能阻塞页面交互。

以上指标不包含第三方模型的网络耗时。

### 9.3 可靠性

- 页面导航、节点移除和模型迟到响应不得导致未捕获异常；
- 标签页关闭、刷新或页面 generation 失效后，不得继续发送新批次，后台应尽快中止该会话的存活请求；
- 同一页面重复点击翻译必须幂等，不得将中文再次翻译；
- 恢复原文必须以本次会话保存的精确值为准；
- 一个批次失败不得清空其他批次的成功结果。

### 9.4 可访问性

- 弹窗和设置页支持键盘操作；
- 所有输入和按钮具备明确 label；
- 状态变化通过可访问的 live region 提示；
- 不只依赖颜色表示成功、错误和进行中。

## 10. MVP 测试网站与验收标准

“测试网站”用于覆盖不同页面结构，“验收标准”用于判断第一版是否真的完成。自动化测试以本地固定页面为准，真实网站只做发布前冒烟测试，避免外部页面变化导致 CI 不稳定。

### 10.1 自动化测试页面

| 编号 | 固定页面 | 覆盖场景 |
| --- | --- | --- |
| FIX-01 | 静态文章页 | 标题、段落、列表、链接、图片说明 |
| FIX-02 | 富文本文章页 | `strong`、`em`、行内链接、多文本节点上下文 |
| FIX-03 | 文档站页 | 正文、行内代码上下文、代码块工具栏、目录和导航排除 |
| FIX-04 | React SPA | 客户端渲染、路由切换、局部更新 |
| FIX-05 | 无限滚动页 | 动态新增内容、可视区域优先、去重 |
| FIX-06 | 正文表单页 | 按钮、placeholder、alt、aria-label |
| FIX-07 | 失败模拟页 | 401、429、5xx、超时、非法 JSON、缺失 ID |

### 10.2 真实网站冒烟测试

发布前至少人工验证：

- 英文 Wikipedia 文章页：传统长文章；
- MDN 文档页：正文、导航和代码块混合；
- GitHub README 页面：复杂站点结构与动态导航；
- 一个公开 React/Vue 内容站：客户端渲染；
- 一个无限滚动内容页：动态加载。

真实站点名单可以在实施阶段替换，但必须保留上述结构类型。

### 10.3 发布验收

MVP 必须同时满足：

1. 固定测试页中至少 95% 的合格英文正文节点被识别并进入翻译流程；
2. 正文根节点之外的导航、侧栏、页脚和广告 100% 不被修改；
3. 元素层级、class、style、href、src 和事件行为不因翻译发生变化；
4. 正文中的代码块及其工具栏、脚本、编辑器和隐藏内容 100% 不被翻译；
5. 模型返回有效结果时，节点 ID 与写回位置 100% 对应；
6. 单节点响应无效时，该节点保持原文，其他有效节点正常翻译；
7. 点击恢复后，仍连接在 DOM 中的所有已修改文本和属性与原值完全一致；
8. 动态内容进入可视区域后，在去抖时间和模型耗时之外自动进入队列；
9. 相同配置和原文命中缓存后，不再发送模型请求；
10. 停止操作完成后，迟到响应不得继续修改页面；
11. 关闭 Popup 后当前翻译继续，关闭标签页、刷新或跨文档导航后不再发送新批次，并取消该会话仍存活的客户端请求；
12. SPA 路由切换后，旧 generation 的响应不得写入新正文；
13. API Key 不出现在页面上下文、Content Script、普通导出文件或明文同步数据中；
14. 401、429、5xx、网络中断和非法响应均有可理解的错误提示，页面保持可用；
15. Chrome 扩展商店禁止注入的页面能够被识别并给出正确说明；
16. 没有用户主动操作时，不读取或发送任何网页正文；
17. 受登录、订阅或付费墙保护且未在当前 DOM 中呈现的内容不会被获取；
18. 并发请求乱序返回时，完整语义块立即写回且不被较早的慢批次阻塞；跨批次语义块仍整体写回，失败节点可以单独重试，已成功节点不重复请求；
19. 所有 P0 自动化测试通过，真实网站冒烟测试没有阻断发布的问题。

翻译语言质量受用户选择的模型影响，不作为单一自动化发布门槛。默认 Prompt 仍需使用固定英文样本进行人工评审，确认没有明显漏译、解释性输出或格式污染。

## 11. 发布策略与里程碑

发布渠道分阶段开放，但工程从第一天按 Chrome Web Store 标准设计。

### R1：GitHub 开源开发

- GitHub 公开源代码；
- 使用 Apache-2.0；
- 提供构建、测试和本地加载说明；
- 开发期使用 unpacked extension；
- 不作为普通用户稳定版本宣传。

### R2：GitHub Releases 开发者版本

- 发布构建后的 unpacked ZIP、校验值和变更日志；
- 面向开发者和愿意手动安装的早期用户；
- 版本更新由用户手动下载和重新加载；
- 通过公开 Issues 收集网页兼容性问题。

### R3：Chrome Web Store 测试版本

- 完成全部 P0 验收、安全审查和隐私材料；
- 先以 Unlisted 方式测试商店安装、自动更新和审核材料；
- 验证 GitHub 开发版配置导出到商店版配置导入的迁移流程。

### R4：Chrome Web Store 正式公开

- 商店版作为普通用户主要安装方式；
- GitHub 继续提供源代码、开发文档、问题反馈和开发者版本；
- 商店稳定版与 GitHub Release 使用清晰的渠道和版本标记。

详细任务、当前状态和阶段退出标准见[项目状态与开发路线图](development-roadmap.md)。
